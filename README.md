## 架构

```
 内容（Markdown）          规则与登记                 页面模板                 发布
 ─────────────────       ─────────────────       ─────────────────       ─────────────
 src/content/<栏目>/ ┐   src/columns.ts          src/pages/   网址与页面一一对应
 每个栏目一个目录    ├─▶ 栏目登记表          ─▶   src/layouts/ 页面骨架          ─▶ GitHub Actions
 src/content/pages/  ┘   src/content.config.ts   src/components/ 页头、目录等       构建并发布到
                         每类内容可填的字段       src/styles/  颜色、字体、排版        GitHub Pages
```

- **内容与代码分开。** 文字和图片只放在 `src/content/`；改内容不需要碰代码，改外观也不需要碰内容。
- **一张栏目登记表。** `src/columns.ts` 列出全部栏目。导航、首页汇总、标签、RSS、资源发布都读这张表，新增栏目时它们自动跟上。
- **三层页面骨架。** 全站外壳（页头、页脚、深色模式）→ 栏目目录页 / 内容页 / 独立页面。所有栏目共用同一套内容页骨架，栏目之间的差别在各自的页面文件里补充。
- **外观集中管理。** 颜色、字体、尺寸只在 `src/styles/tokens.css` 定义一次，换配色只改这一个文件。
- **不依赖框架。** 页面由 Astro 在构建时生成纯 HTML，样式是原生 CSS，浏览器端只有几段很短的脚本（深色模式切换、后台入口、目录侧栏），写作页 `/write/` 另有自己的脚本。不使用 React、Vue、Tailwind 等 UI 框架。

| 技术 | 用途 |
|---|---|
| [Astro](https://astro.build) 7 | 把 Markdown 和模板生成静态网页 |
| unified（remark / rehype） | Markdown 处理；对话分段等自定义规则写成插件，在 `src/plugins/`。写作页预览用同一套插件 |
| Sveltia CMS 0.237.0 | 网页版内容后台，直接读写本仓库 |
| KaTeX（remark-math、rehype-katex） | 数学公式：构建时排好版，读者浏览器不运行脚本；字体随网站发布，页面有公式时才下载 |
| GitHub Actions + GitHub Pages | 自动构建与托管 |

## 内容的组织规则

### 栏目、独立页面、标签

| 类型 | 是什么 | 例子 |
|---|---|---|
| 栏目 | 一类按日期排列的内容，有自己的目录页，进入首页汇总和 RSS | 文章、项目、技术理论 |
| 独立页面 | 不按日期排列的单页，网址在站点根目录 | 关于 |
| 标签 | 跨栏目的分类，由内容里的 `tags` 自动汇总，无需登记 | 建站记录、随笔、AI对话、学习日志 |
| 目录 | 栏目内部的分级，一个页面只在一个目录里；目录里可以再放目录或文章 | 技术理论的话题（ROS、基础设施）、话题下的系列或章节、项目（Robotics-lab）、项目下的开发日志 |

栏目之间是平行关系，没有哪个栏目独占首页。栏目数量刻意控制在少数几个（博客主人 2026-10-18 决定），栏目以下用目录分级（2026-10-20）。新开栏目由 AI 按 `AGENTS.md` 中的步骤完成，涉及五处文件；漏改任何一处，构建会直接报错并指出缺什么。

目录和标签分工不同：目录决定页面放在哪里、网址是什么，一个页面只有一个位置；标签是跨位置的检索，一篇可以打多个，例如 `学习日志` 把 ROS、学习路线各门课、项目里的日志按时间汇总在 `/tags/学习日志/`。话题与标签可以同名（如话题 ROS 下的文章也打标签 ROS），这是博客主人 2026-10-18 的决定。

### 目录树

栏目里的每个页面有一个「类型」：

| 类型 | 是什么 | 网址 |
|---|---|---|
| 文章 | 一篇内容，下面不能再放页面 | 文件夹路径，如 `/theory/ros/notes/2026-10-18/` |
| 目录 | 可以再放目录或文章。正文是简介，可以不填：不填时目录页列出里面的内容；填了则像项目介绍一样显示正文，内容在侧栏里 | 文件夹路径，如 `/theory/ros/notes/` |

- 页面的位置就是它的文件夹位置：`src/content/theory/ros/notes/` 在目录 ROS 里。层数不限，建议不超过三层，网址太长不好记。
- 目录里的顺序：子目录在前（「排序」数字小的在前，没填按日期），文章在后（按日期从早到晚）。
- 目录也有日期；在年份目录里，目录的日期按它里面最新的一篇文章算，所以有新文章的目录会排到前面。
- 目录设为草稿时，它里面的页面也一起不发布。
- 文章、有正文的目录进入首页汇总、标签和 RSS；没有正文的目录只用来归类，不进入。
- 每一层目录都要有自己的 `index.md`，文章下面不能再放页面；不符合时构建失败并指出是哪个页面。
- 话题由博客主人维护。技术理论的一级目录就是话题，出现在 `/theory/` 的话题列表里。学习路线每开一门新课（如鲁棒控制、滑模控制），就在技术理论下新开一个话题，与 ROS 并列，按开课顺序排在后面；原来的「控制理论」话题因此删除，控制类的课用标签 `控制理论` 汇总（博客主人 2026-10-21）。

### 每个页面是一个文件夹

```
src/content/posts/hello-world/
├── index.md      正文
├── cover.jpg     这个页面自己的图片、音频、视频、PDF……
└── bgm.mp3
```

文件夹名就是网址的最后一段（`/posts/hello-world/`），放在目录里的页面，网址前面是目录的路径。页面私有的素材与正文放在同一个文件夹，删除页面时素材一起删除；目录文件夹里的子文件夹如果有 `index.md`，那是下一层页面，不算这个目录的素材。全站共用的素材放在 `public/`，后台上传的共用素材在 `public/shared/`（网址 `/shared/`）。

### 每篇内容可填的信息

| 字段 | 必填 | 说明 |
|---|---|---|
| 标题 | 是 | |
| 类型 | 否 | 文章（默认）或目录，见上方「目录树」 |
| 日期 | 是 | 决定排序与年份分组 |
| 摘要 | 否 | 用于搜索引擎与 RSS |
| 标签 | 否 | |
| 更新日期 | 否 | |
| 草稿 | 否 | 勾选后不发布，素材也不发布 |
| 对话对象 | 否 | 仅「文章」，写对话记录时填，如 `Claude Opus 5.5` |
| 批注 | 否 | 仅「文章」，显示在正文之前，如这段对话为什么值得留下 |
| 排序 | 否 | 只对目录有效，数字小的排在前面 |
| 正文 | 文章必填 | 目录的正文是简介，可不填 |

放在哪个目录不是一个字段，由页面文件夹的位置决定：写作页里选「放在」，后台里在左侧进入目标目录再新建。

数学公式用 LaTeX 写：行内 `$E=mc^2$`，独立成行的用 `$$` 上下包住。正文里要写美元符号时写 `\$`，否则两个 `$` 之间的文字会被当成公式。公式写错不会导致发布失败，错处显示为红字。

与 AI 的对话记录发在「文章」里，加标签 `AI对话`，正文用单独一行的 `@me` / `@ai` 标出每段发言的开始。字段缺失或格式不对时，构建失败并指出是哪个文件、哪个字段。

## 内容如何发布

```
写作页 /write/ 发布 ─┐
后台 /admin/ 保存 ───┼─▶ 提交到 main 分支 ─▶ 自动构建（通常一两分钟）─▶ 网站更新
AI 推送或合并 PR ────┘
```

### 在前台写文章

先在 `/admin/` 登录一次（同一个浏览器），之后：

| 想写的 | 入口 |
|---|---|
| 栏目下的文章或目录（如新项目、新话题） | 栏目目录右上角的「+」 |
| 某个目录里的文章或子目录 | 目录页右上角的「+」，或目录侧栏底部「在「某目录」里新建」 |

- 写作页先选「栏目」「放在」（哪个目录）和「新建」（文章或目录），再填标题、网址名、标签、摘要和正文（Markdown）。网址前面会显示完整路径，如 `/theory/ros/notes/`，网址名只填最后一段。新建目录后，写作页自动切到这个目录，接着写第一篇即可。正文上方的工具栏可插入标题（二至四级）、粗体、斜体、链接、列表、引用、表格、代码、代码块、公式、公式块和图片；选中文字再点按钮即套上格式，`Ctrl+B` / `Ctrl+I` / `Ctrl+K` 为粗体、斜体、链接，`Ctrl+Z` 可撤销。
- 「预览」与上线后的排版一致（公式、对话分段都会显示），只是代码不高亮、图片不压缩，这两项在发布时处理。
- 图片直接粘贴、拖进正文或点「图片」选择，插在光标处，和文章放进同一个页面文件夹。Markdown 图片不能设置大小和文字环绕，按正文宽度显示。
- 文章的网址名默认是当天日期，目录的网址名需要自己填，都可用英文或拼音（如 `ros2-params`）；与所选目录里已有的页面重名时不能发布。
- 正在写的内容（含图片）自动保存在当前浏览器，关掉页面再打开会恢复。
- 点「发布」后文章和图片作为一次提交写入仓库，一两分钟后上线。勾选「存为草稿」则不公开。
- 登录 8 小时后过期，发布时会提示重新登录；已写的内容不会丢。
- 写作页只能新建。修改、删除、移动旧页面仍在后台进行。

- **后台保存即发布。** 后台的每次保存直接提交到 `main`，不经过 PR 检查。如果某次保存导致构建失败，网站停留在上一个版本，不会出现坏页面；失败记录在仓库的 Actions 页面。
- **AI 可直接发布。** AI 在本地构建通过后直接推送到 `main`，或者走 PR（GitHub 先构建一次、不发布），通过后自行合并。涉及网址、外观或内容的改动，先经博客主人确认。
- **仓库是唯一的内容来源。** Notion 等外部素材由 AI 改写成博客后放入仓库，网站不引用外部平台的文件链接。

## 注意事项

| 事项 | 原因 |
|---|---|
| 页面文件夹名建好后不要改，页面也不要随意移动到别的目录 | 文件夹路径即网址，改名或移动后旧链接失效。后台禁止改名，但允许移动（编辑页的上级文件夹） |
| 独立页面不能与已有网址重名，如 `tags`、`admin`、`posts` | 重名的页面会被跳过。构建会报错拦下 |
| 单个文件不超过 100MB | GitHub Pages 的限制；大视频宜放视频平台后嵌入 |
| 博客页面不加载第三方脚本（统计代码、外部组件等） | 后台登录令牌存在浏览器里，与博客同域名，第三方脚本能读到。评论等功能需选用隔离在 iframe 里的方案 |
| 写作页与后台共用同一个登录令牌 | 在后台登录后，同一浏览器的写作页才能发布；退出后台登录，写作页也随之不可用 |
| 后台登录令牌泄露时，到 GitHub 撤销 | 令牌有本仓库（访问令牌方式）或全部公开仓库（GitHub 登录方式）的写权限 |

```
├── .github/workflows/      自动构建与发布
├── AGENTS.md               AI 维护规范（CLAUDE.md 指向它）
└── README.md               本文件
```

站名和首页介绍文字在 `src/consts.ts`，可直接修改。

## 本地运行

需要 Node.js 22 或更高版本。

```bash
npm install        # 首次
npm run dev        # 本地预览 http://localhost:4321，含草稿
npm run build      # 生成正式网站到 dist/
```
